# Intl, regex deadlines and Test262

Requested 2026-09-09, continuing from `2519fc1`. This document records the design before implementation and will record actual validation outcomes.

## Regex isolation

Run the standalone regress algorithm in a sibling `bluejs-regexp-worker` process. Both compilation (including parser literal validation) and matching use a bounded request/reply channel. A parent deadline covers worker IO and algorithm execution; timeout kills and reaps the worker and joins its IO thread before returning a resource error. Later operations start a fresh worker. Do not use detached matching threads or cooperative cancellation as a hard timeout. UTF-16 input and capture ranges/names cross the protocol losslessly. Cache one compiled pattern per worker; no compiled regex executes in the BlueJS process. Discover the installed sibling binary or an explicitly configured `BLUEJS_REGEXP_WORKER` path; fail closed if unavailable. The host must ship the helper beside its executable. Defaults and configurable VM limits will be tested through the public pipeline, including catastrophic backtracking and recovery.

## Internationalization

Target published ECMA-402 edition 13 (June 2026), verified at the [official publication page](https://ecma-international.org/publications-and-standards/standards/ecma-402/), rather than the living 2027 draft. ICU supplies locale/case/collation algorithms and data; BlueJS implements observable argument conversions, option order, builtin objects/descriptors and exceptions. Scope follows the preceding String task: Intl.Collator, Intl.getCanonicalLocales, Intl.Locale, its Locale-info query methods and the three locale-sensitive String methods. `Intl.NumberFormat` now delegates `format`, `formatToParts`, `formatRange`, `formatRangeToParts`, `resolvedOptions` and `supportedLocalesOf` to the host-neutral Phase 25 service. Its typed mathematical-value bridge preserves exact base-10 strings and BigInts rather than first converting them to `f64`; the range methods also preserve ECMA-402 part ownership. The direct pinned NumberFormat inventory passes, but this remains an incomplete implementation until the provider supplies full locale compact/unit/currency patterns. `Intl.DateTimeFormat` now owns its branded service state and implements construction/call, `supportedLocalesOf`, bound `format`, `formatToParts`, `formatRange`, `formatRangeToParts` and `resolvedOptions` through ICU4X date/time semantic skeletons. Its exact requested field set is selected at runtime, including weekday/era, partial calendar fields, hour-only and fractional-second forms; unsupported ICU4X combinations are formed from a semantic superset and remove only unrequested fields while preserving field order. Its direct, versioned Jiff bundle pins IANA TZDB `2026c`, exposes that release at runtime, case-normalizes every bundled IANA Zone-or-Link identifier without silently replacing a Link with its target, accepts and normalizes ECMA-402 `±HH`, `±HHMM` and `±HH:MM` fixed offsets, and calculates offset/DST transitions independently of machine zoneinfo. A valid TimeClip endpoint outside Jiff's civil-year range uses its equivalent position in the Gregorian 400-year cycle to select a named zone's recurring IANA offset; this preserves the ISO fields and weekday rather than rejecting the endpoint, but is not historical zone data for that remote year. `formatRange` and `formatRangeToParts` reject an `undefined` endpoint before either `ToNumber`, retain ordinary `ToNumber` and `TimeClip`, and do not add a start-after-end rejection. For Gregorian ranges containing a date and requesting neither a zone name nor fractional seconds, the production default is ICU4X's CLDR `DateRangeFormatter`. ICU's side spans are normalized to ECMA-402 serialized-part ownership: an equal field emitted once is `shared`, a repeated field remains endpoint-owned, and literals adjacent to a shared field or bridging the endpoints are `shared`. The ECMA-402 whole-pattern branch remains: if the formatted endpoints are identical, every part is `shared`. The bounded compatibility formatter is intentionally separate, not an equivalent ECMA-402 range implementation: it remains in use for requested zone names, time-only and fractional-second skeletons, non-Gregorian calendars, a host's explicit ICU4X opt-out, and Temporal plain values. It preserves current output while ICU4X gains the required input/data paths. `Temporal` has a deliberately bounded typed-value bridge for all four DateTimeFormat formatting entry points: ISO Instant strings are parsed to checked epoch nanoseconds; `Instant` keeps ordinary time-zone formatting while selecting its type-specific defaults; ISO plain date/time types preserve their local calendar fields, ignore the formatter time zone and suppress its zone name; and calendars/types are checked before direct or range formatting. `Temporal.ZonedDateTime` remains rejected by the DateTimeFormat methods, while `Temporal.ZonedDateTime.prototype.toLocaleString` delegates with the value's own time zone. This is not a claim of a complete Temporal API. ICU4X 2.3.0 is consumed through the pinned compatibility fork and remains an implementation slice rather than a claim of full DateTimeFormat or ECMA-402 conformance: localized long zone names and broader Test262 validation remain required. DisplayNames, DurationFormat, ListFormat, PluralRules, RelativeTimeFormat, Segmenter and supportedValuesOf retain bounded data coverage. The complete non-Temporal pinned `intl402/` selection passes **2,656/2,656 modes** (1,328 files; 803.9 seconds; `intl402/Temporal/` explicitly excluded), validating the present API surface without claiming complete CLDR, Temporal, or ECMA-402 conformance.

## Implemented behavior and deployment

`VmConfig::regex_timeout` defaults to 250 ms per compilation/match. Parser literal validation uses that same default independently of VM configuration; `ParseError.resource` preserves worker/deadline failures instead of mislabelling them SyntaxErrors. Startup has a separate two-second handshake bound. Parent serialization/deserialization and linear metadata scans are outside the regex algorithm deadline. The protocol limits each frame to 16 MiB, validates capture ranges, and preserves UTF-16. A worker caches one pattern per Rust thread, is killed/reaped after a failed transaction and restarts on demand. A worker IO thread only moves bytes; regex work runs exclusively in the child. Regex process memory and ICU/AST/bytecode/allocator storage are not a managed-heap/RSS guarantee.

Build and install `bluejs-regexp-worker` beside every executable embedding BlueJS, or set `BLUEJS_REGEXP_WORKER` to its trusted path. A missing helper fails closed. The standalone algorithm dependency remains regress 0.12.0. ICU4X Collator/Locale/CaseMap use bundled 2.3.0 data; serde 1.0.229 and serde_json 1.0.151 frame the subprocess protocol.

Collator supports sort/search usage, numeric ordering, caseFirst, sensitivity, ignorePunctuation, locale extension keys and supported collation tailorings. Intl.Locale has a private canonical locale slot, so CanonicalizeLocaleList does not invoke a replaced `toString`. Its constructor requires `new`, supports subclass-selected prototypes, validates and applies language/script/region/variants plus calendar/collation/hourCycle/caseFirst/numeric/numberingSystem/firstDayOfWeek options in specification order, and exposes the corresponding accessors, `toString`, `maximize` and `minimize`. Locale-info supplies `getCalendars`, `getCollations`, `getHourCycles`, `getNumberingSystems`, `getTextInfo`, `getTimeZones` and `getWeekInfo`; requested Unicode extensions take precedence and the shared version-pinned provider supplies the bounded defaults. Its capability metadata is an explicit bounded-data contract, not a claim of complete CLDR coverage. Locale negotiation remains service-local until item 4 installs shared `ResolveLocale`; best-fit currently uses the same matching policy as lookup. Casing validates every requested locale, uses the first one and preserves lone surrogates. Canonicalization rejects invalid language tags, underscores, duplicate variants and extensions before applying ICU aliases; it also supplies ECMA-402-visible `islamicc` → `islamic-civil` and `ethiopic-amete-alem` → `ethioaa` calendar aliases that ICU leaves to consumers. `Array`, `Array.isArray`, `Array.prototype.forEach`/`includes`, `Function.prototype` linkage, `Object.isExtensible` and the Math constants/functions provide the ordinary runtime surface exercised by Test262. Math covers `NaN`, signed-zero, integer-wrap, variadic and resource-exhaustion behavior. The sparse-array forEach path only fast-tracks large arrays and falls back when indexed prototype properties exist, preserving callback mutation semantics. Bound comparison identity, descriptors, constructor prototype lookup and GC cycles are tested. General global environment semantics remain a broader engine limitation.

The Test262 assertion host also required basic Error/TypeError/RangeError/SyntaxError/ReferenceError/EvalError/URIError constructors, Error.prototype.toString and cause properties. These are not a claim of complete Error builtins or exception/catch semantics. Host-installed names and typeof consult the existing global object; the later P0.2 slice adds a persistent classic-script lexical environment, while multiple realms and complete global-environment semantics remain absent.
