## Implementation boundary

The accepted parent's `expressions/inference.rs` returns the operand type instead of the
asserted target when `assertion_preserves_runtime_qualifiers` holds. The qualifier
query intentionally regards Unknown/StrictUnknown as unproven, which then leaks
into return checking and declaration inference. A blanket removal of that query
would discard real readonly/opaque protection.

The semantic asserted result and runtime-origin fact must therefore remain
distinct. Compatibility, inference and declaration presentation use the correctly
resolved target; mutation checks retain source provenance through bindings,
properties, substitutions, return annotations and imported callable results.
Related parameter projections require their original binder. Semantic candidate
deduplication must join provenance; flow/cache identities must not erase it.
Existing limits remain enforced, and no `any`/`unknown` recovery or new authority
may replace the promised result. Exact internal representation remains subject
to the public red and these complete behavioral requirements.
