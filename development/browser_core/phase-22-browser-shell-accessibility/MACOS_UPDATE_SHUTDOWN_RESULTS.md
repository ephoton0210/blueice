# macOS owned update and shutdown results

Accepted: 2026-10-09 (Asia/Taipei), on Apple Silicon macOS 26.6.2. Parent commit
`69dd6926797878fccfb57102ab4d147d07e2d25c`. Complete macOS browser delivery remains in progress.

Shutdown now closes automatic/manual core-switch admission, interrupts staged
startup and I/O, drains the owning cutover guard and joins the update watcher
before the launcher returns. Core publication shares the closing lifetime lock;
a closing broker cannot publish another generation. Pending attempts check closure
before each retry/core spawn; startup racing with closure stays owned until drained.
The active generation and staged resources retain their existing owned cleanup.
Initial core Hello reads and writes have bounded startup deadlines.

## Reproduction and regressions

Two public real-launcher regressions first produced one pass and one actual
failure: unchanged-core shutdown reaped its child, while shutdown during a held
automatic replacement left the pending process alive. Both tests passed after
the production correction with the original test files unchanged. The isolated
fixture's fallback containment runs after lifetime assertions. This controlled
startup-barrier reproduction proves the ownership defect; it does not establish
the exact escape stage of the historical retained real-core fixture documented
in the preceding label milestone.

All seven new public regressions pass, covering steady and long-polling shutdown,
automatic/manual startup, a staged peer withholding Hello, a committed generation
and broken update attempts. Natural launcher exit must succeed and each owned
PID must return ESRCH before fixture containment. The focused launcher library,
update and retry gate passed 286 cases across four groups: 273 library methods
and 13 public process regressions, including the seven new methods. There were
zero failures and one existing ignored library case.

The first extended Rust focus run had one fixture failure: a Darwin accepted
socket inherited O_NONBLOCK and its empty read returned errno 35. A direct OS
probe confirmed that behavior. The fixture now explicitly sets the accepted peer
to blocking before its bounded read. The first native focus run passed seven
existing methods and failed before the new lifetime assertions while creating
its private bundle under /private/tmp. The same initializer worked outside the
Runner. Inspection confirmed the XCUITest Runner's sandbox. An intermediate
fixture used its own temporaryDirectory and copied the bundle before quitting
the initial app. No sandbox entitlement or system security setting was changed.
All failed attempts and diagnostic probes remain in the receipt. A second native focus run
still failed at the initial page after the copy succeeded: the fixture had renamed
the real launcher. Code inspection identified that this bypassed its packaged
trusted-frontend path selection.
The private copy now keeps the real blueice-launcher name and adds a separate
wrapper entrypoint. The original service bundle and production sibling resolution
remain unchanged by that fixture correction.
The third eight-method native focus run also retained seven passes and failed
at the initial page. Isolated one-method probes retain their startup diagnostics
and outcomes in the receipt; complete acceptance uses the final focused and
unfiltered runs, rather than any incomplete probe. The second isolated probe
recorded the GUI's explicit EPERM before any launcher PID existed. Read-only
execution/xattr probes found quarantine markers generated by the sandboxed
Runner on copied executables. The final fixture is created by an external test
helper, using the same harness model as the existing SFTP tests. Runner reads its
private metadata and triggers updates over token-authenticated loopback HTTP.
No quarantine flag is removed. The helper cleans up its own files and server;
the application retains ownership of its service processes. A controlled helper
probe checks authentication, path/body rejection, update/finish behavior and that
the original core stays unchanged. Its initial preflight incorrectly expected a
help command that the launcher does not provide; that failed attempt is retained.
The corrected preflight checks the known parser rejection without starting a
service. Earlier failed XCTest assertions bypassed method-local Swift defers;
three retained private copies were explicitly removed after matching creation
times, source hashes, owner and stopped processes. The final case uses XCTest
teardown and harness finally cleanup.

The new XCUITest launches a private copy of the real service bundle, verifies
launcher parentage and core group membership, waits for the automatic replacement
startup barrier and closes the actual browser window. It requires the application,
launcher, serving and pending cores, and owned process group to be gone. PID/group
checks distinguish ESRCH from other errors. The fixture owns only private files;
the application's existing graceful and group fallback containment owns services.
This native end-to-end test alone does not isolate the Rust correction from that
existing fallback; the public red-to-green reproduction does.

## Complete acceptance

Formatting, strict all-target Clippy and the all-target build passed. The complete
Rust workspace passed 7,395 cases, zero failures and 69 ignored cases across 483
result groups. Focused native acceptance passed three protocol/supervision XCTest methods and
five actual-window XCUITest methods without failures or skips. The unfiltered
XCTest/XCUITest suite executed exactly 273 methods: 155 XCTest methods passed,
and the actual-window XCUITest suite passed 117 methods and skipped the same
physical Zhuyin method. That is 272 passes, zero failures and one skip overall.
All 272 parent methods remain present. The skip does not establish physical IME
mapping acceptance.

All final gates share unchanged 1,837 source/build inputs with aggregate SHA-256
`2fdec4252d68a8cf24d0581d14cba04648db6e3bf86efff5daf3c0cc57c0e28e`. Ten strict signature checks passed and ten executable
hashes were recorded. Both Swift app executables contain arm64 and x86_64 slices;
runtime acceptance and Rust service products are arm64. Read-only process audits
confirmed the owned gate, update and SFTP fixture processes/groups were gone and
private roots removed. A separate timestamped audit verified cleanup for all eight
historical native/helper attempts: 21 known groups were absent and 14 roots were
removed. Missing child-group fields in older helpers are retained as missing,
without attributing later PID reuse to those finished tests. Unrelated preexisting processes were preserved using their
original PID, start, executable and parent proof. This increment changes service
lifetime behavior and tests; it introduces no rendering change or tracked images.
